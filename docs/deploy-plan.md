# 网页部署方案（待审阅）

> 状态：**方案稿，未实施**。审阅确认后再动手。
> 目标：让监测数据能在网页上访问（自己远程查看 / 分享给他人）。

## 核心约束（决定方案选型）

1. **B站风控对出口 IP 敏感**：实测数据中心/代理 IP 会被 412/-352 拦截，
   家宽直连正常（见 README 反爬说明）。**采集必须留在本地**，云端只适合做"展示"。
2. **数据在本地 SQLite**：`data/monitor.db` 持续增长，部署方案需考虑数据同步或就地服务。
3. **Web GUI 目前仅监听 127.0.0.1**：远程访问需要隧道或改造。

## 方案 A：本地采集 + 静态报告发布（推荐）

架构：本地每日采集 → 生成图表 PNG + 静态 HTML → 自动推送到 GitHub Pages / Cloudflare Pages。

```
[本机 Windows]                          [GitHub / Cloudflare]
 run.bat / 计划任务 21:30 采集
   → charts.make_dashboard 出图
   → 新增 static_site.py 生成纯静态 HTML 站
   → git push 到 site 分支      ──→    GitHub Pages 自动发布
                                         https://kyo-zzz.github.io/bilibili-monitor/
```

**实现要点**
- 新增 `bmon/static_site.py`：把 Web GUI 的五个页面中"只读"部分
  （总览统计、视频列表、快照表、图表）渲染为纯静态 HTML（Jinja 模板复用 templates/），
  趋势图可内嵌 echarts + JSON 数据文件（或降级为 PNG）
- 新增 `main.py site` 子命令 + 计划任务在每日采集后自动 `git push`
- 仓库可用现成的 kyo-zzz/bilibili-monitor，Pages 指向 `site` 分支或 `/docs` 目录；
  若不想让数据公开，用 Cloudflare Pages + Access 加访问密码，或 GitHub 私有仓库 Pages

**优点**：零服务器成本；采集风控零风险；页面可公开分享；天然有历史版本。
**缺点**：数据每日更新一次（与采集频率一致）；快照/趋势等交互能力弱于动态 GUI；
数据会离开本机（公开仓库=公开数据，需权衡，可用私有仓库缓解）。

## 方案 B：内网穿透，远程直连本机 Web GUI

架构：Web GUI 保持在本机运行，通过隧道暴露给远程浏览器，数据不出本机。

- **Cloudflare Tunnel（cloudflared，推荐）**：免费、无需公网 IP、自带 HTTPS；
  可加 Cloudflare Access 做密码/邮箱验证。缺点：免费版域名是随机/托管域名，
  且本机必须开机联网。
- **Tailscale**：组私有虚拟局域网，仅自己的设备可访问，最适合"只有我用"的场景，
  零暴露面。缺点：分享给他人不方便。
- **frp + 自有 VPS**：灵活但要自己维护服务器与安全（需加鉴权，勿裸奔）。

**实现要点**：仅需 `python main.py gui` 常驻（可注册为 Windows 计划任务/开机启动），
再装对应隧道客户端即可，代码几乎零改动（cloudflared 一条命令）。

**优点**：全功能（快照查询、趋势对比、采集控制都在）；数据不出本机；改动最小。
**缺点**：依赖本机开机联网；分享给他人需额外鉴权配置。

## 方案 C：云服务器部署（不推荐作为主方案）

架构：VPS 上跑 Flask + gunicorn + nginx + HTTPS，直接连云端 SQLite 采集。

**致命问题**：数据中心 IP 采集 B站大概率触发风控（已实测验证），
需要持续对抗，违背项目"低速安全采集"的设计初衷。

若确实要做（比如只监测少量视频、低频请求），需要：
- gunicorn 多 worker + `--host 0.0.0.0`（需把 webui.py 的 127.0.0.1 改掉）
- nginx 反代 + Let's Encrypt HTTPS + Basic Auth 或 Cloudflare Access 鉴权
- 数据同步：本地 monitor.db 定时 rsync/scp 上传，云端只读展示（采集仍在本地）——
  这种"同步式"变体其实接近方案 A，但不如静态页省事

**优点**：7×24 在线、不依赖本机开机。
**缺点**：月费（轻量 VPS ≈ ¥30-60/月）；采集风控风险；安全维护成本。

## 方案对比

| 维度 | A 静态报告发布 | B 内网穿透 | C 云服务器 |
|---|---|---|---|
| 成本 | 免费 | 免费（frp+VPS 除外） | ¥30-60/月 |
| 采集风控 | 无风险（本地采集） | 无风险（本地采集） | 高风险 |
| 功能完整度 | 只读报告 | 全功能 | 全功能（需改造） |
| 数据隐私 | 可选公开/私有 | 不出本机 | 在云端 |
| 依赖本机开机 | 仅推送时 | 是 | 否 |
| 实施工作量 | 中（新增静态生成器） | 小（装隧道客户端） | 大 |

## 推荐结论

- **自己远程看 + 注重隐私**：方案 B（Tailscale 或 Cloudflare Tunnel），当天即可用。
- **想要一个可分享的公开数据页**：方案 B 先顶上，再逐步实施方案 A 做公开静态站。
- 方案 C 仅在"必须 7×24 且接受成本与风控对抗"时才考虑。

也可组合：**B 立即启用（零改动）+ A 作为二期**，两者互不冲突。
